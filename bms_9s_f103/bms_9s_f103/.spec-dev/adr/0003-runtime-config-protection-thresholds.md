# ADR-0003: 保护阈值从运行时配置读取

## 背景

`protection.c` 的保护阈值（过压/欠压/过流/温度等）当前通过编译期 `#define` 硬编码。`can_cmd` 模块接收 CAN 配置命令（ID 0x202）写入 `bms_shared->settings`，但 `protection_check()` 从不读取。这意味着 CAN 参数配置功能对保护阈值完全无效——用户修改阈值后保护行为不变。

## 决定

`protection_check()` 的签名增加 `const bms_settings_t *settings` 参数，所有阈值从 `settings` 读取而非编译期 `#define`。编译期常量降级为出厂默认值（在 `bms_shared_init()` 中设置），CAN 配置命令写入后下一保护周期生效。

## 理由

- CAN 配置功能若不生效是隐蔽的功能缺陷（用户以为改了但实际没改）
- BMS 保护阈值在不同电芯和应用场景下确实需要调整（如 LFP vs NMC 的电压平台不同）
- 出厂默认值保留了"上电即安全"的保障

## 被否方案

- **保持编译期硬编码 + 删除 CAN 配置命令中的保护阈值部分**：以"功能安全"为理由禁止运行时修改。被否理由：(1) 项目不是 ISO 26262 ASIL 级别的功能安全系统；(2) CAN 配置是受保护的（有协议格式校验），不会误触发；(3) 这种做法会大幅降低 BMS 对不同电芯的适配灵活性
